# 《未名之海》游戏设计文档

**Unnamed Sea - Game Design Document**

> **核心定位：第一人称 3D 自由实时动作 RPG；战斗与移动手感优先，钓鱼暂作为未知收获与装备成长入口。**
> 
> **体验主线：从水中获得装备与线索，带着新的战斗方式走向下一片水域，逐渐读懂脚下的世界。**

## 设计与实施状态

- **更新时间**：2026-10-20。本文件是唯一的现行游戏设计文档。后续直接更新本文件，不另建带版本号的副本。（Codex）
- **已确认**：第一人称自由实时战斗，武器与能力并重；取消天赋树。左上为 1—5 五个自由配置的快捷物品位，右上生命，右下能力提示。武器暂自带专属技能；独立共鸣提供遗物能力，另有小幅永久增益收集物。钓鱼等待与咬钩节奏对标《泰拉瑞亚》，旧长等待方案废弃。（Codex）
- **制作优先级**：用简模和紧凑地图尽快交付 5—10 分钟 MVP，先验证移动、攻击、收获与装备变化；暂停主角形象和批量精细资产制作。最近二游主角九宫格仅 02 获得相对积极反馈，仍未选定或批准建模。旧概念图和模型保留为资源，不代表 Demo 的画面门槛。（Codex）
- **暂定与待验证**：钓鱼暂留；核心共鸣遗物先按约 5—6 件规划，可装备共鸣槽先按 3 个试验，最终数量、具体遗物、组合及参数待定。专业药水主要向 NPC 购买，渔获可自制食物。皮肤与盈利可探索，发行模式尚未选择；明确标为“建议”的内容不视作用户已批准实施。（Codex）
- **现有实现**：默认入口 `scenes/combat_mvp.tscn` 已支持第一人称跑跳、简模手部与范围近战、敌人预告、生命与重试，CodeBuddy 钩爪已整合，40 项集成检查通过，组合手感待用户验收。旧第三人称和 2D 系统保留；直射、追踪弹、3D 钓鱼、材料与制造闭环尚未接入，5—10 分钟 MVP 尚未完成。（Codex）
- **内容设计状态**：本文补齐世界历史、人物关系、四片区域、任务与关卡方案，作为后续制作的内容依据。具体数值、首次试玩时长和资源数量是验证目标，不是已实现结果或交付承诺。已确认的核心机制继续沿用。
- **阅读方式**：第 1—2 章说明体验与世界；第 3—6 章规定系统；第 7—10 章约束表现与验证；第 11—13 章给出首段关卡、内容样例和小团队制作顺序。开发者文档包含结局，玩家可见文本须遵守剧透边界。
- **主角与背景**：主角为来历暂不解释的“新来者”；以生活、装备成长和好奇心推进探索。居民、遗物与旧庭构成故事，不赋予主角既定职业使命。
- **参考边界**：二次元形象仅作为美术参考，不据此引入角色抽卡或角色收集系统。

## 一 项目概述

### 1.1 一句话描述
玩家在一片陌生水域的岸边醒来，通过钓鱼、自由实时战斗和装备合成，在这里立足、结识居民，逐步走进更深处的奇异水域，最终发现这片有着天空与潮汐的海洋位于地球内部。

### 1.2 玩家为何愿意继续
一次钓鱼可能带来晚饭、武器材料，也可能捞起一块与远方建筑相同纹样的残片。玩家先因一件新装备想走远一点，随后因某个尚未解释的细节愿意再回来。装备成长支撑探索，探索又让同一件物品获得新的意义。

核心循环沿用：观察水域 → 选择鱼饵并钓鱼 → 获得渔获或遭遇异兽 → 自由战斗 → 收集材料并制作装备 → 挑战新路线 → 带着线索返回聚落。

- 一次短游玩应有一个可说清的收获，例如试出一种武器、修好一盏路灯、找到一种鱼的用途。
- 一个区域应有一个值得记住的场面，例如在半淹的铃塔下钓起失落的钟舌。
- 一段主线应回答一个旧问题，再留下一个具体的新问题，避免全程只说谜语。

### 1.3 目标玩家与游玩节奏
面向喜欢装备搭配、轻探索、收集与环境叙事的单人玩家。玩家可以在安全岸边慢慢钓鱼，也能主动进入危险水域挑战敌人。难度来自观察和走位，而非要求精确到像素的瞄准。

首个完整小体量版本以约 3—5 小时的首次主线路程为内容规划参考，实际时长须用试玩测量。完整收集不计入主线时长；不通过强制刷取、真实时间等待或重复跑图填满时长。

### 1.4 三个可以实际做出的记忆点
**能被读懂的渔获。** 发光鱼、结盐工具和旧铭牌分别指向生态、工艺和历史；图鉴把已获得的信息连接起来。实现上使用已有物品、任务标记和分阶段文本，不增加复杂的推理模拟。

**同一片海的两种感受。** 远看温柔的海湾，在主动投下特殊鱼饵后变成战场。安全岸线、撤退口和明确预告，让安静与紧张的切换由玩家理解和掌握。

**回头看才懂的风景。** 开场看来寻常的灯光与夜色，结尾能与养花笔记里的周期记录对应。惊喜来自前后信息关联，优先复用场景、物件与声音，控制新增制作量。

## 二 世界观与故事

### 2.1 世界真相与居民认知
开发者真相：海洋位于地球内部的巨大空腔中。上方岩穹含有发光矿物，水汽与微粒把光散成淡紫和浅蓝；多数居民一生只见过这片穹光，习惯把它称为天空。这里采用奇幻世界规则，不承担真实地质解释。

居民把生活的水域称为“内潮”，这个称呼只表示被礁环包围的海面。他们懂鱼群、草药、种植和手工，却没有完整的世界剖面图。旧庭里有人记录过天光与生物的关系，留下的零散笔记逐渐成为民间故事。居民说的是自己知道的生活经验，没有一个无所不知的 NPC 故意拖到最后才说出答案。

日夜、天气和特殊事件继续沿用原有机制，设定解释统一：岩穹的明暗周期形成昼夜，冷热空气循环形成风雨；“三日凌空”是三个发光区域经雾层折射后同时显露；“血月”是赤色藻尘染红圆形穹光的罕见渔况。玩家前期只接触民间名称，成因到后期才有证据。

远方看似漂浮的岛屿，主要是被雾遮住基部的高礁和悬出的岩台。场景无需实现漂浮陆地物理、整片海洋模拟或可自由飞行。

### 2.2 世界气质和生活细节
这里有让人安心停留的地方，也有可以主动走向的危险。聚落里有晾干的渔网、被反复补过的衣物、写着当天汤料的木牌；遗迹有锈蚀、沉积与失修，却仍留着普通人使用过的痕迹。故事允许失落，重要任务尽量落在修复联系、送回遗物和理解他人上。

| 元素 | 表现约束 |
|------|----------|
| 远景 | 淡紫浅蓝的穹光、雾中高礁、少量发光水生物；每区保留一个清楚地标 |
| 安全空间 | 暖色灯火、生活声、完整栏杆与可停留座椅；与敌人活动区有明确分界 |
| 危险空间 | 波纹方向异常、旧警示旗、断续金属声；不用整屏变暗掩盖敌人 |
| 建筑 | 木栈道、石屋、半淹庭院与旧工坊相接，呈现居民在古老建筑间继续生活的年代感 |
| 奇观 | 每区集中制作一个主景，其他地点通过构图、色彩与旧模块组合变化 |

### 2.3 世界的过去与眼前的生活
**共居年代。** 更早的居民沿着温暖水域建立庭院、工坊和公共汤棚，用发光矿物照明，在岸上种草药、修工具。他们把不同水域的植物与鱼类带回庭院养护，也记录天光变化与生物习性。留下来的纹样、器皿和观察笔记首先属于日常生活。

**封庭年代。** 数十年前，一场地面塌陷与涨水使旧庭的部分通路封闭。留在外围的居民逐渐形成今天的灯汀湾；内部建筑被植物和异兽占据，旧庭中的守卫装置仍重复着封门时的保护命令。陆铆和苏苇记得当时的迁居与互助，但不知道更古老的世界结构。旧庭没有一夜消失的神秘王朝，也不需要凭空增加一位幕后主使。

**游戏当下。** 灯汀湾依然可以生活，只是旧门另一侧越来越少有人走过。钓起的奇怪旧物、仿佛从地下传来的鸣声、夜间映出陌生纹理的鱼鳞，让人意识到熟悉的生活之外还有许多东西。新来者的出现没有引发末日危机；玩家因眼前的需要、居民的牵挂和自己的好奇，逐步进入更深处。

### 2.4 主角的留白与可见形象
主角没有预设的职业任务，居民只称其为“新来的”。开场直接从陌生岸边醒来：附近有可用的枝条、草绳和旧工具，远处传来生活声。怎样来到这里暂不解释，叙事从玩家能够行动的当下开始。主角拥有普通生活常识；身世与过往留出想象空间，主线不以记忆缺失或追查来历推动。

最初的愿望很具体：弄到吃的，找到能歇脚的地方，学会应对岸边异兽。有了第一件自己做的装备后，玩家开始想去看看那片更深的水、找到某个人提过的旧庭，弄清这里为什么有如此奇怪的天空。情感变化通过与居民熟悉、聚落里有了可返回的位置表现，不要求主角背负拯救世界的职责。

衣袋里可留一只磨旧的怀表作为轻量伏笔。表针正常走动，却与当地天光的明暗周期对不上；早期只留下观察，终局再用环境记录说明这里的昼夜不由普通日照形成。怀表不作开门钥匙、战斗能力或时间谜题，不据此确定主角来自地表，也不解释具体进入方式。

主角身份继续留白，现已确定第一人称。MVP 优先表现手中武器、鱼竿与必要手部占位，不依赖完整人物模型；性别、脸型、发型和服装暂停定稿。已有旅行者模型与概念图保留，后续是否用于界面、叙事或完整身体表现另行判断。（Codex）

### 2.5 四片区域的地图结构
世界以固定地图和分区加载实现。宏观路线为“灯汀湾 → 鸣礁洼地 → 沉钟旧庭 → 无昼井庭”。每区包含一处安全停留点、一个主地标、两段可探索路线，以及一个连接下一片区域的出口；区域内部通过岸线、栈道和旧闸廊步行连接。水面提供景观与钓鱼面，首版不要求玩家游泳、潜水或驾驶船只。

灯汀湾是持续返回的生活中心。其余区域通过恢复旧升降平台或打开已有栈桥接通捷径；基础路线沿用机关与场景状态，不以尚未验证的机动能力作强制门槛。后续可给钩爪和位移工具增加可选捷径，但不因此扩成自由建造或无限攀爬系统。跨区转场可用短黑场与水声完成。远景海面不可达时，以礁壁、岸线和雾层表现边界。（Codex）

| 区域 | 玩家任务与场景记忆点 | 推进依据 |
|------|----------------------|----------|
| 初始水域 灯汀湾 | 在聚落立足，探索被异兽占据的旧门；暖灯旁有半座铃塔 | 战胜背灯蟹，取回被它卷入巢中的旧闸钥，打开旧闸廊 |
| 深水区 鸣礁洼地 | 找到低鸣的来源与庭院遗迹；管状礁体发出不同高低的声音 | 经过守路精英取得旧庭通行牌，进入通往工坊的升降台 |
| 深海区 沉钟旧庭 | 走进被水淹过的生活旧址；工坊的巨大钟罩悬在岸边 | 击退占据内庭水渠的盘索鳗，取得通往高处庭院的机关部件 |
| 神秘区域 无昼井庭 | 进入封闭的观天室；暗色海面倒映出上方连续的结构纹理 | 使守庭装置停机，打开遮板，看见完整地层图与岩穹 |

初始区的安全岸和外侧深水闸口属于同一片制作地图，首个 BOSS 位于后者；“深水区”章节则指随后展开的完整区域。水深用于区域气质与渔获层级，主角主要在岸上活动。

### 2.6 区域关卡细节
**灯汀湾。** 主路从苇叶浅滩通向汤棚和修缮屋，再沿半月岸线走到旧铃塔。左侧短支路能从高处看见闸口和大蟹的背灯；右侧支路通向安静钓台，提供材料和一件有来历的旧物。闸口战场与居民区用矮礁和窄廊分开，敌人不追入聚落。打开闸门后形成回到汤棚的短环路，玩家直观看见自己的行动改变了地图。

**鸣礁洼地。** 以环形礁地构成两条路线，一条视野开阔但有侧向移动敌人，一条更短但转角处需要先观察。远处持续可见三根高低不同的鸣礁柱，避免仅靠小地图找路。玩家从一次单敌横移战学会判断弹道，再面对两种敌人的组合。主线依靠普通调查与战斗推进，声音线索同时有飘带和字幕等视觉提示，不把听力辨音作为通行门槛。

**沉钟旧庭。** 岸侧工坊、上层连廊、下层水渠围绕同一个钟罩布置，制造高度变化，但同一场战斗中的敌人尽量留在可同时观察的平台。桥下可见的鱼影提示另一处钓点，奖励愿意回头寻找入口的玩家。打开内庭通道时仅切换预设水面高度、通路碰撞和少量摆件，不模拟整片流体。BOSS 出场点与玩家活动岸台相邻，能够用近战攻击到它的露出部位。

**无昼井庭。** 主路靠连续的暖白庭灯引导，中央水面开阔而安静。先让玩家穿过一段没有战斗的种植长廊，看到熟悉植物的干枯根系、矿物光带与旧笔记互相对应。终战之后沿一段安全坡道到达观天室，以已有远景显露岩穹曲面。终局奇观采用背景模型、雾与灯光变化，不增加可探索的第五张大地图。

### 2.7 主线叙事与结局
**第一段 在这里留下来。** 阿汀给新来者一碗汤，教玩家认识安全钓点和附近的危险。玩家发现最安静的外侧钓台被旧门挡住，门后的背灯蟹正拖着一盏从庭院拿走的灯。准备装备、主动挑战并取回旧闸钥后，玩家打开通向鸣礁的路，也获得一条回到汤棚的捷径。离开是因为想看看更远的水域，而不是接受职业派遣。

**第二段 传闻背后的生活。** 鸣礁的低鸣被当作海兽呼吸，靠近后才发现部分声音来自水流穿过空心岩道。钓起的器物与旧庭餐具具有相同纹样，显示这里曾有人长期生活。陆铆在玩家需要时说明旧门和升降台的用法，帮助继续探索；随后找到的主线迁居记录交代数十年前封庭的经过，也让他愿意谈起过去。生活遗物与可选支线补充不同人的经历。

**第三段 天空离我们有多远。** 无昼井庭留有照看植物的人记录过的天光周期，内容与玩家怀表上的时间不一致。通往观天室的守庭装置仍执行早年的封闭命令，把靠近者挡在门外。玩家战胜它后，操作已有拉杆打开遮板，再沿安全通路走向观察窗。战斗解除眼前阻碍，观察与阅读完成发现，不以杀死某只怪物自动解决整个世界。

结局保留一条完整主线：观天室展开完整地层剖面，同时标出外侧地表、连续岩层和内海所在空腔；图中矿物带和旧庭位置与玩家沿途所见对应。窗外岩穹与地层图共同证实这里位于地球内部。主角怎样进入仍可留白，这个答案与世界位置分开处理。

回到灯汀湾时，阿汀为新来者留了一碗热汤，陶满想看新发现的材料，其他人有一句和共同经历有关的回应。结尾通过熟悉的生活说明玩家已与这里产生联系。通关后沿用当前地图继续钓鱼与收集，不重置居民成果，不要求主角立即离开，也不承诺地表篇。

### 2.8 伏笔和剧透控制
| 早期可见证据 | 当时可以成立的理解 | 终局获得的新解释 |
|--------------|--------------------|------------------|
| 夜空中三处亮斑相对位置始终一致 | 安静而稳定的星群 | 固定在岩穹上的发光区域 |
| 怀表走时与天光明暗总对不上 | 当地一天似乎格外长或短 | 穹光周期并非普通日照周期，不能单独证明主角来历 |
| 不同区域钓起同纹样的陶片和合金碎片 | 旧居民喜欢相似的工艺 | 如今分开的区域曾属于连续的共居庭院 |
| 养花人的笔记写着“越往高处，天越有纹理” | 光和雾造成的观察误差 | 岩层本身逐渐进入视野 |
| 墙上残图中的连续弧线 | 庭院装饰或生长纹样 | 完整地层图中的岩层轮廓 |

每个核心推论至少由场景证据和一条可重读记录共同支撑。主线必经路径提供理解结局所需信息；可选收集补充人物生活，不把重要答案藏在极低概率物品里。前期图鉴、任务名、物品描述和载入提示不直接写“地心”“岩穹真相”等开发者词汇。

## 三、核心玩法

### 3.1 钓鱼系统（入口动作）

#### 3.1.1 基础机制
钓鱼是游戏的"入口动作"——通过钓鱼获取物品、触发战斗、发现新区域。具体交互如下，读者无需了解其他游戏即可实施：

| 要素 | 详细说明 |
|------|----------|
| 基础循环 | 投钩 → 等待 → 鱼漂动 → 拉钩 → 获取物品 |
| 钓具质量 | 鱼竿与鱼饵等影响钓力，钓力改变咬钩频率与收获；不再用最低 15 秒等待惩罚初始鱼竿。旧脱钩率并非《泰拉瑞亚》已核实规则，另行验证（Codex） |
| 鱼饵系统 | 不同鱼饵吸引不同类型的物品（普通/稀有/BOSS） |
| 水域环境 | 温度影响可钓物类型，高温水域可增加危险渔获；环境参数的具体范围待验证 |
| 钓鱼保底 | 连续 N 次未获得符合条件的稀有收获，第 N+1 次触发稀有保底；具体条件与 N 按 6.3 验证 |

#### 3.1.2 等待与收竿节奏
用户要求钓鱼等待对标《泰拉瑞亚》，废弃每级鱼竿分别配置很长等待再额外长时间收线的方案。[官方 Wiki 的 Catch frequency 与 Reel in time](https://terraria.wiki.gg/wiki/Fishing)说明咬钩由钓力与随机检查决定；示例平均咬钩时间为 25 钓力约 6.36 秒、66 钓力约 3.10 秒、125 钓力约 1.50 秒，并非每次保证该时长，低钓力可能连续检查失败而等更久。（Codex）

**实现目标。** 对标随机咬钩、鱼漂反馈和及时收竿；咬钩后正确收竿即可尽快揭晓，不再强制额外等待 10—20 秒进度条。后续实现时记录所参考版本、检查频率与钓力规则，以独立代码重建并实测分布，不把上面的平均值直接填成固定倒计时，也不把旧注释“直接对标泰拉瑞亚”当作已完成证据。首轮先测上述钓力档，六根鱼竿的映射与完整环境修正再定；开发用固定触发入口仍保留。（Codex）

**当前差距。** `data/rod_data.json` 仍保留旧 `wait_min/wait_max` 和 `reel_min/reel_max`，初始档分别为 15—45 秒、10—20 秒；`scripts/fishing.gd` 的旧流程尚未迁移。本轮是设计更新，不能据此声称游戏里已经缩短等待。原有水域、渔获类别和未讨论的合成规则不因节奏对标而全部改写。（Codex）

#### 3.1.3 渔况系统（关键创新点）
渔况系统是让钓鱼体验丰富化的核心机制：
- **幸运值**：影响稀有率和脱钩率
- **食物/热汤**：提供临时BUFF（如钓上的鱼可做生鱼片、寿司、鱼汤等）
- **撒饵**：提高特定类型吸引力
- **天气/时间**：不同时段、天气影响可钓鱼物品
- **特殊事件**：血月、三日凌空等，出现特殊物品和BOSS

### 3.2 战斗系统（核心玩法）

#### 3.2.1 战斗方式：第一人称 3D 自由实时动作战斗

玩家自由移动、转向、选择攻击方向，以武器设计提供命中宽容度。参考泰拉瑞亚的自由战斗思路，在 3D 空间中重新验证距离、方向和反馈，不照搬 2D 的命中表现。

- 不要求先锁定敌人，不强制角色持续面向某个目标，不让相机持续跟随敌人。
- 近战通过挥击范围、扇形攻击和范围伤害提供命中宽容度。
- 普通远程武器可提供轻度辅助瞄准，保留玩家对攻击方向的控制。
- 追踪弹是特定武器或弹药的能力；不默认所有攻击都会追踪。
- 辅助瞄准力度、追踪能力和攻击范围通过试玩调整，不预先承诺所有武器都高命中。

#### 3.2.2 操作与镜头验证方案

采用第一人称与屏幕中央准星：玩家控制观察与攻击方向，自由移动和转向；钓鱼也保留第一人称，能看清鱼漂、收线反馈与周围危险。战斗中相机不自动持续跟随敌人。近战、直射和追踪的自由战斗原则继续有效。（Codex）

| 输入 | 原型验证用途 |
|------|--------------|
| WASD | 自由移动 |
| 鼠标移动 | 控制镜头与观察、瞄准方向 |
| 鼠标左键 | 朝玩家选择的方向攻击，不要求先锁定目标 |
| 移动能力操作 | 优先验证跑动与跳跃的连贯手感；闪避、滑铲等具体动作及按键组合通过原型选择，不同时堆入首轮 |
| 武器切换操作 | 对比三种攻击；具体按键通过原型验证 |

第一人称近战与钩爪小样已接入，移动时默认奔跑、按住 Shift 走路，空格跳跃／翻越、Ctrl 蹲伏／滑铲、左键挥击、右键钩爪，操作入口见 13.6。滑铲包含轻微压低、侧倾、起伏与平滑回正，额外动效可通过 JSON 的 `slide_camera_motion_scale` 调弱或关闭，基础蹲姿与碰撞保留；不主动改变鼠标俯仰。简模手部已有程序过渡，其余武器、正式动作及完整设置面板仍待开发。近墙收手为初步处理，复杂姿态与弹体穿墙须后续验证。（Codex）

#### 3.2.3 首轮武器验证

| 攻击类型 | 验证目的 |
|----------|----------|
| 范围近战 | 通过挥击或扇形范围，让距离与方向容易判断 |
| 带轻度辅助的直射攻击 | 保持自由瞄准，观察辅助是否抢走攻击方向 |
| 追踪弹 | 验证特定武器的追踪特色与目标选择是否符合玩家预期 |

先比较三种攻击在同一小场景中的体验，再扩充武器种类。角色动作、攻击范围、命中特效与伤害反馈应清楚对应，不以追踪或扩大范围掩盖反馈问题。

#### 3.2.4 武器类型
武器是游戏的核心乐趣来源，设计多样化：

| 类型 | 示例 | 特点 |
|------|------|------|
| 近战 | 潮弧刃、开礁斧、回灯镰 | 近距离挥击，用清楚的范围覆盖形成命中宽容度 |
| 远程 | 鸣礁弓、线膛枪、盐壳手炮 | 中远距离，消耗弹药，部分攻击有轻度辅助 |
| 魔法 | 引灯杖、潮纹铃、折光杖 | 消耗 MP，可设计范围或追踪效果 |
| 召唤 | 召唤笔、驱魔笔 | 召唤帮手战斗 |

### 3.3 装备系统（完整版）

#### 3.3.1 装备格子

| 部位 | 说明 |
|------|------|
| 武器 | 主要输出，决定战斗方式 |
| 头部 | 头盔或兜帽，提供防御 |
| 身体 | 铠甲或外服，提供主要防御 |
| 手部 | 护手，提供装备属性 |
| 腿部 | 腿甲或长裤，提供装备属性 |
| 鞋部 | 鞋或靴，提供移动相关加成 |
| **饰品栏 x5** | 被动与功能修饰，可改变移动、工具或续航；具体主动能力归属仍待定（Codex） |

#### 3.3.2 合成系统
合成是游戏的重要乐趣来源：
- **基础合成**：材料 A + 材料 B = 装备 C
- **套装效果**：同系列装备提供额外加成
- **稀有合成**：特殊组合可创造传说级装备
- **材料与装备来源**：钓鱼获取、普通敌人与 BOSS 掉落、NPC 商店购买、既有采集点；用途在配方中明确。NPC 可收购渔获与材料，出售补给及部分装备；具体货单与价格后续验证，暂不扩展动态经济。（Codex）

### 3.4 怪物与BOSS系统

#### 3.4.1 怪物设计原则
- 每种怪物有独特的 AI 行为模式
- 怪物掉落包括：材料、装备、武器、稀有道具
- 稀有怪物有低掉落率的极品装备
- 同一敌人的材料应有可理解的用途，让玩家因想试一件装备而自愿再次挑战。主线必需物避免依赖极低掉率。

#### 3.4.2 BOSS设计
BOSS 触发方式灵活多样：
- **钓鱼触发**：使用特殊鱼饵可钓出 BOSS：在指定水域使用明确标识的特殊鱼饵，引来对应 BOSS；首次尝试前展示危险提示，保留退出准备的机会
- **剧情触发**：推进故事自动触发
- **事件触发**：血月、特定时间等条件成立时出现

**BOSS 特点**：多阶段 AI + 独特机制 + 专属掉落表

### 3.5 功能装备与移动能力（2026-10-20）
**用户确认的方向。** 武器和能力都重要，武器暂自带专属技能，同时保留传送、位移和钩爪等非伤害工具，以及独立的遗物共鸣能力；不是把全部成长都变为加伤害，也不是用能力替代有趣武器。原有五个饰品栏先保留为完整版本结构；共鸣槽、饰品槽和五个快捷物品位用途不同，MVP 不一次做全。（Codex）

| 内容 | 体验目标 | 当前决策状态 |
|------|----------|--------------|
| 基础移动 | 喜欢《THE FINALS》与《Apex Legends》式连续、可控、能与战斗衔接的移动 | 手感方向已确认；跑跳、加减速、空中控制及坡阶处理先做小样，具体参数未定 |
| 钩爪 | 参考探路者的牵引、绕点摆荡与松手后飞出的爽感，适应 3D 高差空间 | 已纳入 MVP；CodeBuddy 初版已整合，组合手感和障碍边界待验收，不承诺完整复刻（Codex） |
| 传送与短位移工具 | 改变站位和探索路线，不要求附加伤害 | 方向记录；距离、资源消耗、障碍检查与取得时机待定 |
| 功能饰品 | 用装备搭配改变玩法，如工具冷却、空中操作或补给效率 | 后续验证样例；不是已批准的具体属性表 |

**当前落地，待组合试玩。** 用户将清怪与机动战斗同时纳入 MVP，CodeBuddy 的摆荡钩爪已整合进第一人称近战场，保留松钩惯性和起钩助推。先不同时加入滑墙、滑铲、攀爬、连跳和多种传送；高台保留普通坡道，剧情推进不因尚未验证的机动系统重写。（Codex）

钩爪原型需要验证可附着表面、射程、失败反馈、绳索被遮挡后的行为、转角碰撞、松手速度、落地恢复与读档重置；这些是测试问题，最终规则与数值未定。高速移动时敌人的攻击预告、命中方式和场地尺寸也必须一起测试，不能只提高玩家速度。（Codex）

### 3.6 钓鱼的地位与差异化（暂定）
钓鱼暂时保留，不强行寻找一个只换动画的替代动作。它负责“水面以下不可见、投入后快速揭晓”的期待，战斗和装备负责拿到东西以后还能做什么。普通渔获不必全部变成需要击杀的敌人；钓鱼也不能成为玩家每次想战斗前都必须等待的手续。岸边常驻敌人、稳定材料来源与补给入口继续保留。（Codex）

**Codex 建议：让玩家选择未知的范围。** 在同一水域，用鱼饵与可见水迹表达大致收获类别和风险，例如普通鱼饵偏向补给，壳片饵偏向装备材料或异兽；精确结果仍未知。收获用于制造能改变操作的武器、工具或饰品，使“我想试一种新玩法”成为继续垂钓的理由。该方案属于待审核提案，MVP 先借现有随机池和两类清楚的结果验证，不新增复杂生态模拟。（Codex）

**可替代动作的候选，均未采纳。** 一是“牵引打捞”：向可见水下残骸投出抓钩，短时拉取未知旧物，适合沉钟旧庭并可复用钩爪的表现；二是“投饵引获”：投饵后依据水迹决定收获或迎战，比固定站立等鱼更主动。前者需要旧物分布，后者可能失去钓鱼的安静间隔；暂不因此改掉已有钓鱼流程。鱼笼与长时间放置不适合本轮追求的短反馈。（Codex）

**验证方式。** 按 3.1.2 对标《泰拉瑞亚》咬钩节奏，记录等待分布、收竿到揭晓的时间、用途理解和重复意愿；旧 15—45 秒等待已废弃，代码尚待替换。固定遭遇测试入口保留。未知结果不依靠大量无用垃圾或极低概率主线材料撑时长。（Codex）

## 四 进度系统

### 4.1 成长结构
**已确认取消天赋树。** 成长由武器与装备、可装备的共鸣遗物、小幅永久增益收集物共同承担；暂不新增分点、洗点或天赋界面。经验等级的必要性仍待定，不额外承诺一套角色升级线。（Codex）

| 层次 | 获得什么 | 当前决定 |
|------|----------|----------|
| 武器 | 有辨识度的攻击与武器专属技能 | 暂定技能跟随武器，武器本身与能力同样重要 |
| 共鸣遗物 | 装备后获得能力，换搭配改变玩法 | 首批约 5—6 件遗物；共鸣槽暂按 3 个试验，不是已定最终数量 |
| 永久增益收集物 | 使用或取得后获得小幅永久改善，例如生命上限 | 用户已确认与共鸣并存；具体物品、增益和上限待定 |
| 防具与饰品 | 防护、被动与功能修饰 | 沿用已有框架，避免与共鸣重复提供同一能力 |
| 药水与食物 | 有持续时间的补给或强化 | 专业药水主要向 NPC 购买，鱼类等可自制食物 |

永久小幅成长不等于获得一件遗物后永久拥有其全部技能，也不要求集齐遗物才能正常战斗。永久物品与已拥有遗物应有明确存档记录，不能靠重复读档无限叠加；具体来源与数值未定。（Codex）

### 4.1.1 遗物共鸣
遗物来自水中、怪物或探索到的旧物。世界观上，它们保留自身力量，装备后回应玩家；不增加现实科技解释或改写主角身世。遗物可带“频率”标签，如水、雷、铁、光，用于组合判断。玩家认可这种收集与组合方向，具体规则仍需原型验证。（Codex）

**槽位与使用。** 共鸣槽暂以 3 个作测试起点，从约 5—6 件核心遗物中选装；没有固定 1 主武器 + 1 副武器限制。换手中武器不自动卸下共鸣；右下显示已装备能力与其操作、消耗和冷却。能力快捷键及是否另设独立工具位需结合五格快捷栏一起测试，避免重复摆放与按键过多。（Codex）

**组合样例，未定稿。** 潮汐贝壳可给短冲刺，雷鳗牙可给电链，旧钩爪可给牵引，灯芯可给照明弹。“水＋雷使冲刺带电”“铁＋光使钩爪兼具照明”及同频加成为 CodeBuddy 的候选；不是已批准的最终遗物表或固定冷却减免。MVP 之后先用两件遗物验证单独使用和一个组合，不预做所有排列。照明影响场景亮度与可见性，不直接强改相机视野角。（Codex）

**保留选择意义。** 数量少不等于全部都是纯数值增长；优先提供新动作、探索用途或玩法变化，同时让武器的攻击方式保持价值。核心机动、主线必要能力与重要永久增益不只藏在极低概率钓鱼池，具体保证途径在区域设计时落实。（Codex）

### 4.2 区域推进与装备目标
| 阶段 | 玩家需要学会的事情 | 下一次探索的动力 |
|------|--------------------|------------------|
| 灯汀湾 | 看懂钓鱼反馈，学会自由攻击与闪避，完成首次制作 | 获得有明显攻击差异的新武器，打开闸廊 |
| 鸣礁洼地 | 应对横移敌人，选择适合自己的攻击类型 | 从材料用途推测下一件装备，进入旧庭 |
| 沉钟旧庭 | 组合装备、饰品和食物，处理两种敌人配合 | 完成一种稳定搭配，进入观天室 |
| 无昼井庭 | 运用已学会的走位和方向判断 | 看懂世界证据并完成终战 |

通行条件用“恢复设施、完成明确挑战、取得任务物”表达。装备强度让挑战更容易，但不把单一稀有装备设为硬门票。每类首轮武器都应有完成主线战斗的办法；特定武器可以更方便，不承担强制解谜钥匙。

### 4.3 经济与奖励的补充原则
普通材料服务常用制作，稀有材料用于有特色的可选装备。商店出售基础补给，帮助玩家恢复探索能力；高价装备可以作为长期目标。配方界面展示材料来源与已有数量，第一次拿到关键材料时提示一条近期能完成的用途。

主线任务物采用固定场景交互、明确任务结算或必得的首胜奖励。随机渔获与掉落继续负责惊喜和重复游玩；首次通关不依赖等待罕见天气、抽中极稀有物或跨现实日登录。

### 4.4 失败与恢复的验证方案
失败惩罚尚未锁定。首个试玩建议采用就近安全点恢复、保留任务进度和已取得关键物品的宽松方案，先验证玩家是否愿意再次尝试。落水边界、战败返回位置、资源消耗和存档时点须在关卡测试中一起确认；不在文案中假定死亡必定掉光物品。

## 五 人物与关系

### 5.1 常驻角色与服务
五个功能角色沿用向导、商人、军火商、护士和炼化工匠的定位。首段只完整制作向导与工匠；其余服务按区域推进加入。NPC 名称与性格采用下列内容稿，最终外观随美术样例调整。

| 角色 | 服务和个人愿望 | 可见辨识点 |
|------|----------------|------------|
| 阿汀 汤棚照料者 | 教程与主线引导；想让聚落继续成为大家能歇脚的地方 | 围裙、补过的灯罩，习惯先确认玩家有没有吃饭 |
| 陶满 杂货商人 | 买卖材料、食物与基础装备；喜欢弄清旧物的用途，也想看看久未见过的老友 | 绑满小抽屉的货架，给每件旧货贴来路标签 |
| 岑弦 修械师 | 武器与弹药；想做出普通渔民也能用好的自卫工具 | 整齐的袖口与耳侧护片，说话简短，反复确认试用感受 |
| 苏苇 护理员 | 支付硬币恢复生命；想补齐旧庭居民迁居后的消息 | 围裙、保温壶、随手记名字的小册子 |
| 陆铆 炼化工匠 | 炼化、配方与遗物复原；想重新走进封闭多年的旧工作间 | 粗布手套、一副不同颜色的镜片，紧张时数零件 |

### 5.2 人物小传与角色弧
**阿汀**照看汤棚和门口的小灯，习惯给迟到的人留一份热汤。开场她会教新来者先找食物、试试手里的工具，再去危险的旧门。她不掌握世界真相，知道的是哪里能歇脚、哪种鱼好吃、谁愿意帮忙。她担心主角走远后受伤，却渐渐学会认真听新发现，而不总用“这里一直这样”结束话题。结尾那碗预留的汤，比一份正式身份更直接地说明玩家在这里有了位置。

**陶满**夸耀自己知道所有东西的价钱，却一直没卖掉一串只值几个铜币的旧风铃。那是儿时在庭院里认识的朋友送的。对方搬走后，两人一直没有机会再见。完成支线后，风铃挂回聚落入口，摊位出现来自更深水域的小物件。用旧物和陈设表现人与人的联系，无需模拟动态贸易。

**岑弦**珍惜准确和可靠，曾做出威力大却让使用者难以控制的武器。她的任务让玩家分别试用范围近战、直射和追踪攻击，再用对话反馈偏好。剧情不替玩家宣判哪种武器最好；她最终学会为不同的人提供不同选择，与自由战斗理念一致。

**苏苇**的册子里记录的首先是名字，其次才是伤势。她希望补齐旧庭迁居簿，确认一些熟悉的人后来在哪里安顿下来。支线可以有遗憾，但至少带来可证实的消息与一次告别。完成后聚落里多出一盏纪念灯，不用新增角色模型表现每一位历史人物。

**陆铆**年轻时在旧庭工坊学手艺，封庭后只愿修眼前的小东西，不再提旧工作间。他以为自己留下的粗糙补丁早已失效，玩家却在旅途中看见它还支撑着别人用过的桌子和钓台。需要通行时，他直接说明升降台与旧门的用法；获得迁居记录后，他再想起当年大家如何彼此照应。个人支线让他愿意谈感受，机关信息始终不受支线和后续记录限制。

### 5.3 关系与聚落变化
阿汀与陶满常为“该不该去更深处看看”争论；岑弦向陆铆学习材料处理，却不认同他对旧设计的执着；苏苇记得陆铆帮过的人，知道怎样让他面对旧事。人物关系通过短对话和任务前后的一句回应体现，不做大量两两好感分支。

聚落只维护少量明确阶段：新来者暂住 → 旧门打开 → 带回新物与消息 → 旧庭重新可达 → 结局。每个阶段改变两三处灯光、摆件或台词，让回家有反馈。首个小体量版本不加入婚恋、送礼养成或全员日程模拟。

### 5.4 对话语气与样例
阿汀：“灯还亮着，就先把今晚过好。明天的路，我们明天一起看。”

岑弦：“别急着告诉我伤害高不高。先说，你想打的那只，打中了没有？”

陆铆：“这道补丁是我打的。以前觉得难看，现在倒靠它认出了路。”

普通服务对话以两三句为宜，第一次介绍只解释当前需要的动作。长背景进入可选询问和可重读记录。主线任务栏保留下一步，玩家跳过对话后仍能继续。

## 六、特殊系统

### 6.1 炼化系统
炼化台把渔获、残骸等原始物转成可用于制作的材料。玩家能在操作前看到输入、消耗数量和已知结果；未知结果以明确标识显示，不暗中销毁任务物。基础流程：
- **位置**：NPC 小屋内的炼化台
- **功能**：将原始物品转换为材料或其他物品
- **体验**：放入物品 → 点击炼化 → 获得结果
- **配方**：部分物品需要特定配方才能炼化

### 6.2 图鉴系统
- 记录已发现的所有物品、怪物、NPC
- 每条目有基础信息 + 获取方式 + 用途
- 收集度提供成就感。
- 每条目分成“怎么获得、能做什么、已经知道的故事”三层，实用信息先显示。未发现内容提供区域级线索，避免直接泄露结局。
- 同一遗物可随主线更新一小段解释，旧描述保留为观察记录；用任务状态切换文本实现，不要求生成式 NPC 或实时推理。

### 6.3 钓鱼保底（待验证）

- 钓鱼保底用于缓解连续无有效收获的挫败感，次数与规则尚待验证；第 3.1 节中的 N 是占位参数。
- 验证时明确计数是否按水域或鱼饵区分、何种收获重置计数、切换水域是否保留进度。先测试一种易于解释的方案，再决定细则。
- 主线推进不依赖该机制补救低掉率。关键任务物有明确获得途径，保底服务可选收集。
- 二次元角色美术与抽卡机制独立决策；当前原型不纳入角色抽卡、特殊通货抽卡或角色收集系统。

### 6.4 烹饪系统
用户确认保留自制食物路线：用自己钓到的鱼等材料准备食物，与 NPC 出售的专业药水并行。以下效果为现有样例，具体强度、持续时间和叠加关系待测，不固定为“食物只能弱、药水必定强”。（Codex）
- **生鱼片**：小幅提升攻击力
- **寿司**：提升幸运值
- **鱼汤**：缓慢恢复 HP
- （更多食谱待设计）

### 6.5 天气/时间/事件系统

| 类型 | 示例 | 影响 |
|------|------|------|
| 时间 | 日夜循环 | 夜间可钓特殊物品 |
| 天气 | 晴/阴/雨/雪 | 影响温度和可钓鱼物品 |
| 特殊事件 | 血月、三日凌空 | 出现特殊怪物/BOSS/稀有物品 |

---

### 6.6 药水与补给（新增方向）
专业药水主要由 NPC 出售，用户也认可后续材料合成药水的可能；与钓鱼后自制生鱼片、鱼汤等食物形成两条补给路线。NPC 可以出售更专门的效果，但药水不要求全部有代价，食物也不限制为弱化版药水。两类通过效果、用途、取得成本区分，具体货单、配方与叠加规则待定。（Codex）

“扣除部分生命，暂时换取更高移速”继续作为功能药水候选，不照搬其他游戏名称和数值。MVP 不同时展开完整炼药与料理体系。（Codex）

建议先验证一瓶回血补给，再独立测试“疾行药剂”占位：饮用前明确显示生命代价和持续时间，低血时能否使用、是否致死、是否叠加、取消与存档时如何处理均须先定规则。移速收益要能在绕敌与撤退中感知，不能把喝药变成平时赶路的必做动作；具体规则尚未批准。（Codex）

## 七 美术与声音

### 7.1 优先验证的美术方向

**Demo 采用简单低多边形场景、清楚配色与手持装备优先的制作方式。** 用户指定《渔力全开》为本轮视觉投入的参考：允许地形、NPC 和场景道具简陋，先把眼前的武器、敌人行为与反馈做清楚。它是制作取舍参考，不承诺第一版达到其完整商业版本的系统量；此前丰富概念图是后续愿景，最终美术风格仍未定稿。（Codex）

- **视角**：已定第一人称与中央准星；鱼竿、武器、交互反馈优先可读。（Codex）
- **色调**：沿用神秘而温柔的淡紫、浅蓝与深蓝微光水面。
- **光照与效果**：柔和环境光、少量自发光、水下发光生物，保证鱼漂和战斗目标清晰。

### 7.2 角色设计与资源路线

- **玩家**：MVP 使用第一人称碰撞体、视点和手持装备占位；完整身体、精细脸部及服装不是开工条件。已有主角素材保留，暂无新模型生成任务。（Codex）
- **验证顺序**：先确认移动、攻击、持竿、手持物遮挡与近墙表现，再按实际需要完善手部和装备动作。（Codex）
- **立绘用途**：2D 立绘可用于概念设计、对话和界面；不再默认以单张立绘放入 3D 场景满足自由镜头和实时战斗需求。
- **怪物**：轮廓清晰、强调未知感，攻击预告和受击反馈可辨认。
- **装备与武器**：让外观变化和攻击方式可感知；避免角色、服装和特效遮挡目标。

- **参考边界**：动漫风格不绑定抽卡系统，不以大量角色或精细服装作为首轮交付要求。

### 7.3 四区的视觉语汇
灯汀湾以浅青水、奶白木板和暖琥珀灯为主；鸣礁洼地转为灰紫礁石、白色盐边和随风摆动的长布；沉钟旧庭使用锈橙、深蓝与少量铜绿；无昼井庭降低饱和度，用连续暖白灯和大块静水突出终局视线。

颜色和轮廓优先于细密纹理。第一人称会贴近岩壁、栏杆与工作台，优先解决尺度、碰撞和交互边界；不为装饰纹理推迟可玩交付。可交互物、危险预告和普通装饰使用一致且可区分的形状语言；关键提示不只依赖红绿颜色差别。（Codex）

### 7.4 动作与效果清单
第一人称首批表现包括手持待机、跑动时的轻微装备响应、持竿／抛竿／收线、攻击、受击与失败提示。先用简单变换或基础动作让出手和判定对应，不要求完整全身动画。镜头旋转与移动不能因为挥击或命中停顿而失去控制；近战轨迹和有效范围须一致，追踪弹不能被装饰粒子淹没。精细手指、全身脚步、表情和衣摆在玩法通过后安排。（Codex）

怪物按行为需要配置待机、移动、前摇、攻击、受击和倒地。相同骨架允许复用，但不同攻击方向必须有可辨认的姿态变化。BOSS 阶段转换优先用壳片、灯色与动作节奏表达，避免为每阶段重做一个完整模型。

### 7.5 音乐与环境声音
聚落采用轻而稀疏的拨弦与风铃；外海以水声和拉开的音程留出空间；旧庭加入低频机械节拍，终局重新出现聚落旋律。先制作一段聚落音乐、一段探索音乐、一段可循环战斗音乐和一小段结局变化，区域差异用环境层补充。

鱼漂咬钩、拉线成功、攻击落空、命中、受伤、敌人前摇和获得稀有物都需要明确且可区分的声音。音乐不能盖住战斗提示；重要音效配合视觉提示，提供音量分类、字幕、镜头震动强度和闪烁减弱设置。

### 7.6 界面布局方向
| 位置 | 内容 | MVP 取舍 |
|------|------|----------|
| 左上 | 1—5 五个快捷物品位，玩家自由配置武器、鱼竿、工具或消耗品 | 明确不是强制五把武器，也不固定主副武器；选中态、编号与数量清楚（Codex） |
| 右上 | 角色生命 | 数值与变化清楚；法力、弹药按武器实际消耗补充，不和生命混淆 |
| 右下 | 当前武器技能与已装备共鸣能力提示 | 清楚区分来源、按键、冷却和消耗；未实现能力不放假按钮（Codex） |
| 中央 | 小准星、交互对象与短提示 | 不遮住敌人前摇、鱼漂或弹道 |

上述角落分布与五格快捷栏由用户确定；能力按键、共鸣槽最终数量与界面缩放待实机验证。快捷栏是物品取用入口，不等于五件被动装备同时生效；共鸣装配在独立位置管理，天赋树已取消。背包与工作台需说明配方缺口和材料用途；安全交互与战斗的切换不能导致丢失鼠标或卡住操作。（Codex）

### 8.1 场景与状态的落地约束
按“常驻角色与界面、区域场景、敌人和可交互物、任务数据”组织实现。先让一张地图完整读写状态，再复制做其余区域。区域解锁、关键物领取、设施修复和 BOSS 首胜需要独立状态，读档后不会重复领取或把通路关闭。

四区使用固定场景、有限环境变体和少量任务开关。程序化地形、整片海洋物理、多人同步、开放式建造、可驾驶船只与实时生成剧情不进入当前首个小体量版本。原有采集和挖掘的材料来源可以先表现为有限资源点，不扩展为可破坏的体素世界。

### 8.2 给 AI 制作工具的输入边界
可用本文件介绍整体项目，但本轮必须明确只实现第 13 章的当前小目标；第 11 章的完整首段是 MVP 之后的目标。先做第一人称移动和一次短战斗，再接通钓鱼、掉落与制作；不因上传了完整 GDD 就让工具同时实现所有角色、地图和后续能力。（Codex）

交付验收看可运行行为、资源文件和逻辑是否能理解与继续修改。第三方工具的上传格式、导出能力和与 Godot 的兼容性需在实际试用时确认；本文件不假定上传整份文档即可自动完成全游戏，也不假定不同工具产物可以直接互通。

| 第一人称镜头与准星 | 鱼漂、近墙、近战交错、高速转向与手持物测试 | 方向距离清楚、不晕、视野不被武器遮挡（Codex） |
| 高机动 | 先跑跳与坡阶，再单独对比一种移动工具 | 有可控的连续操作，能服务战斗，失败可恢复（Codex） |
| 武器技能与共鸣 | 比较武器专属技能、遗物能力和一个组合的理解与使用 | 技能暂跟武器，独立共鸣并存；不再验证天赋树（Codex） |
| 钓鱼辨识度 | 比较短等待、收获风险提示和装备用途 | 惊喜之外有主动选择，玩家愿意再来一轮（Codex） |
| 武器辅助力度 | 同场景对比范围近战、轻度辅助直射、追踪弹 | 不抢走攻击方向，不频繁选错敌人 |
| 钓鱼等待与保底 | 记录有效操作间隔、连续无收获体验 | 既保留期待感，也能持续推进探索 |
| 环境参数 | 分别验证温度、天气、时段对渔获的解释性 | 旧稿未定义的 PC 值不直接新增为一套数值系统 |
| 装备与技能数值 | 先完成一次材料到装备的成长，再扩展搭配 | 新装备的作用能被玩家感知和解释 |
| 战败与落水处理 | 观察失败后能否理解原因并愿意重试 | 返回距离、资源损失与挑战难度匹配 |
| 内容规模与设备目标 | 完成首段后统计实际制作耗时和运行表现 | 再确定全篇工期、目标配置与最终数量 |

任何涉及改动已确认核心机制的后续建议需单独讨论；具体怪物、名字、景物和支线可在同一文件中持续打磨。

## 十、核心设计原则总结

### 10.1 游戏为什么好玩
收获的价值来自用途和期待。普通材料能支撑近期制作，少见渔获能改变下一次选择，遗物能让玩家更理解已经走过的地方。每个区域至少提供一个新战斗问题、一件有用的新装备和一次可见的场景变化。

用试玩回答具体问题：玩家会不会主动换武器，是否知道材料能做什么，是否愿意返回一个旧钓点，是否记得某个 NPC，以及结局是否让早先线索变得清楚。创新性通过这些行为验证，不预先宣称一定好玩。

### 10.2 参考作品如何转成独立规则
《泰拉瑞亚》保留为交流时的辅助参考。本项目实际采用的内容必须用自身规则说明清楚，制作与试玩不要求参与者玩过参考作品。

| 参考简称 | 本项目需要独立实现的说明 |
|----------|------------------------|
| 自由战斗 | 玩家自由移动和选择攻击方向；相机不持续锁住敌人。武器分别用范围、轻度辅助和特定追踪能力改善命中体验 |
| 武器差异 | 换装备后，攻击轨迹、距离、资源消耗或覆盖方式发生可观察变化，而非只换伤害数字 |
| 特殊鱼饵召唤 | 玩家在指定水域使用有危险说明的鱼饵，引出专属头目；挑战前有准备空间和清楚的奖励线索 |
| 向导 | 教会当前动作，解释已见物品用途，在主线卡住时指出下一步；不能预知玩家尚未发现的世界真相 |
| 炼化 | 在固定工作台放入材料，确认消耗，得到已知或明确标识的未知结果；配方与材料来源可查询 |
| 功能饰品与非伤害工具 | 装备可改变移动、补给与探索方式；武器、工具、饰品和药水分别说明能力，不用“像泰拉瑞亚”代替规则（Codex） |
| 第一人称移动参考 | 《THE FINALS》提供速度与连续操作的体验目标；《Apex Legends》探路者提供钩爪参考。以独立代码制作自己的小样，不承诺直接移植商业游戏实现（Codex） |

本项目目前希望用“水中未知收获 → 装备改变操作 → 主动选择下一次风险”形成辨识度；是否成立要用 Demo 验证，不能把“3D 泰拉瑞亚”本身当成特色。原有渔获线索与聚落变化保留到后续内容阶段。参考作品的角色、专名、美术、地图、具体配方和代码不直接搬用。（Codex）

**本轮调研与边界（2026-10-20）。** 已确认参考对象为 Dazed Games 的[《渔力全开 / How to Fish》Steam 官方页面](https://store.steampowered.com/app/4001890/?l=schinese)，浏览了“关于此游戏”的官方实机动图：画面可见低多边形人物、鱼与手部，大块岸地、蓝色水面及直接的持竿／战斗展示。我们采用的制作判断是减少环境细节、优先近景工具与清楚反馈；这是基于展示画面的观察，不是对其开发成本、全部内容或性能的测量。该作支持 1—4 人，而本项目继续做单机，不引入联机物理范围。（Codex）

[参与开发的 Pingle Studio 案例页](https://pinglestudio.com/cases/the-finals/)列出《THE FINALS》使用 Unreal Engine 5；[Embark 官方说明](https://www.reachthefinals.com/patchnotes/s6teaser)也强调快速流畅移动。参考的是体验目标，不要求更换本项目引擎。[Godot 的 CharacterBody3D 文档](https://docs.godotengine.org/en/stable/classes/class_characterbody3d.html)提供可脚本控制的速度、坡面和碰撞能力，适合作为独立移动原型基础；能否达到期望手感仍取决于控制参数、碰撞、镜头和反复试玩。不能直接把 UE 或商业游戏移动系统导入 Godot。（Codex）

[EA 官方能力指南](https://help.ea.com/en/articles/apex-legends/abilities/)可核对探路者的钩爪与动力小子的耗血加速。此处只借鉴功能与体验，不采用角色设定、美术或版本数值；开源实现若后续使用，需先核对许可与 Godot 兼容性。当前未获取或移植《Apex Legends》源代码。（Codex）

### 10.3 MVP 开发里程碑
开发按第 13.2 节的六阶段推进。先交付可走动样机，再加入战斗与钓鱼成长闭环，整理为可分享的 5—10 分钟 MVP；验证后才扩成第 11 章的灯汀湾首段。每一轮交付可运行结果，避免并行维护多套计划。

### 10.4 自由战斗原型验收

- 在单敌、多敌、敌人横向移动与近距离交错场景中，对比三种攻击的方向、距离、命中反馈和操作理解。
- 检查辅助瞄准是否抢走攻击方向、追踪弹是否频繁追错目标；不以强制相机转向补偿问题。
- 检查第一人称武器、手部与特效是否遮挡视线，鱼漂和敌人是否容易观察；高速转向、跳跃落地和近身攻击不应引起明显眩晕。（Codex）
- 跑通移动与观察 → 抛竿与收线 → 遭遇异兽 → 自由攻击与闪避 → 掉落 → 返回探索的流程。
- 记录试玩结果后调整辅助力度、追踪能力和攻击范围；三种攻击验证后再扩充武器内容。

## 十一 首段试玩与关卡验收

### 11.1 首段范围
先完成灯汀湾一个能从开场玩到旧门开启的完整段落，包含安全聚落、两个钓点、两段野外路线、一条捷径和一个头目场地。首次游玩约 25—40 分钟是节奏目标，允许玩家慢慢钓鱼和探索。正式计入时长前，需要排除读文案和反复迷路造成的虚长。

最低内容为一名占位主角、阿汀与陆铆两名 NPC、两种普通敌人、背灯蟹、三种攻击、少量渔获材料、一次完整制作和闸门状态变化。其他 NPC 的工作位置可以先用摆件暗示。首段不承担技能树、全部天气、所有装备部位和多区域旅行的首次教学。

### 11.2 玩家流程与反馈
| 路段 | 玩家行为与可见结果 | 验证问题 |
|------|--------------------|----------|
| 苇叶浅滩 约 3 分钟 | 自由移动、转镜头，使用简陋钓具；远处暖灯提供方向 | 玩家是否知道能去哪里，是否能看清角色与鱼漂 |
| 安静钓台 约 5 分钟 | 完成垂钓，查看渔获用途；岸边固定旧庭陶片提供第一条历史线索 | 不依赖 NPC 长讲解，玩家能否理解收获有什么用 |
| 外侧浅岸 约 5 分钟 | 经历钓鱼引来的异兽遭遇，学习攻击、闪避和撤退 | 玩家是否看懂怪物从哪里来，是否能自由选择方向 |
| 修缮屋 约 5 分钟 | 用鱼类产物与战斗材料完成一次制作，再试用武器 | 制作是否有明确因果，新武器是否明显不同 |
| 旧铃塔路线 约 7 分钟 | 遭遇横移敌人与双敌组合，找到支路钓点，打开回营捷径 | 新装备是否鼓励继续探索，路线是否便于辨认 |
| 深水闸口 约 10 分钟 | 得到特殊鱼饵，了解警告并主动挑战背灯蟹；取回钥匙打开旧门 | 三类武器是否都有机会输出，胜利是否改变地图 |

各路段时间只用于安排内容密度，不设置倒计时。测试版本可用明确标记的固定结果复现教学遭遇；普通钓鱼仍遵循既有随机池与保底。正式首段若迟迟未随机引出异兽，应由岸边可见敌人提供学习与材料来源，避免为完成教学无休止垂钓。固定陶片和主线钥匙不混入低概率随机池。

三类攻击先在同一开发测试场比较，再进入叙事获取流程。故事首段可依次提供基础近战、可制作直射武器与可选追踪武器；如果连续介绍过密，开发测试入口仍保留三类对比，玩家流程减少一次教学。不能因为追踪武器尚未取得就卡住头目。

主角在苇叶浅滩取得可直接装备的潮弧刃，首次异兽遭遇不要求先制作武器。首次到达修缮屋时，陆铆直接开放鱼骨炼化与盐壳手炮配方；普通鱼、跳蟹壳片和所需工具均能在闸口之前获得，配方不藏在可选支线里。原型先用少量材料完成一次制作，再根据实测调整数量。

陆铆同时提供使用普通材料制作基础弹药的入口；修缮屋补给箱提供首段可补领的法力恢复用品。补给不依赖未登场的军火商、头目掉落或下一片区域。补领范围、恢复量和消耗是试玩参数，后续再接入完整经济；所有耗尽情况都能回到近处补给后继续。

### 11.3 钓鱼到战斗的衔接
异兽结果出现时，先给出异常水纹、拉线音和明确的岸边落点，再进入攻击。玩家可以取消当前收线表现并恢复移动；装备的武器能直接接续战斗，不需要在多个背包页面寻找。具体切换键仍按第 3.2 节验证。

水域数据须指定可生成敌人的岸台和有效导航区域，不能让敌人出现在玩家背后、屋内或无法攻击的深水中。安全钓点通过清楚的水域说明排除强制战斗；危险钓点在交互前提示可能出现异兽。是否保留被打断的鱼饵和等待进度属于原型细则，统一验证后写入界面提示。

### 11.4 自由战斗的空间规格
旧灰盒建议普通战斗区从约 18—24 米有效宽度、头目场地从约 28 米直径起测；它们不是第一人称高机动版本已验证的规格。迁移后须随速度、跳跃、攻击距离与钩爪试验重新测量。场地至少允许横向避开一轮攻击、绕到敌人侧面、退回可观察距离；高低差与钩爪横梁先在测试角落验证，再进入正式关卡。（Codex）

探索窄廊不安排必须在原地解决的高压战斗。大柱、树干与高墙放在场边；近景摆件应低于关键攻击动作，或在相机接近时妥善处理遮挡。初期先测试 1—3 只普通敌人同时进攻，减少屏幕外连续攻击。敌人追击边界必须清楚，玩家撤退后不会把整片地图的敌人带回聚落。

危险预告至少有身体动作与地面范围或弹道表现，声音作补充。相机贴墙、角色近距离交错、水面高亮、连发特效和追踪弹同时出现，均需作为专项场景检查。优先删掉干扰阅读的装饰，再增加特效密度。

### 11.5 首个头目背灯蟹
背灯蟹把从旧庭拖来的落地灯架背在壳上，用光吸引水生物。玩家先从远处看见缓慢移动的灯，以为有人提灯散步；走近后才发现灯下面有一副长满贝壳的甲壳。它把门边的杂物卷入巢中，旧闸钥也卡在壳缝里，既形成首次挑战，也让通行物的来源可见。

模型以一个甲壳主体、四条主要支撑肢、双螯和可独立摆动的背灯组成。入场用水花遮蔽短距离上岸，战斗全程在可步行岸台完成。攻击时不要求精确瞄准微小弱点，近战能接近其侧面，直射与追踪都能命中可见主体。

| 招式 | 玩家能看到的预告和行为 | 应对与输出机会 |
|------|------------------------|----------------|
| 扫灯 | 抬起背灯与一侧螯，显示前方扇形方向，再横扫 | 后退或向侧后方闪避；横扫结束后停顿 |
| 拖灯冲撞 | 压低身体，灯光收束到直线路径；前摇结束后方向固定 | 横向移开，利用冲撞结束的恢复动作攻击；不追着玩家持续急转 |
| 盐壳落点 | 甲壳抖动，三处圆形落点依次显示，随后碎壳落下 | 离开预告范围，在剩余空地继续输出 |

首轮可从扫灯和冲撞两招起做，确认好玩后接入盐壳落点。约半血时改变已有招式组合和间隔，复用模型与动画；转阶段有明显停顿和灯色变化，不突然加入大量小怪。预告时长、伤害、恢复窗口与追踪能力均作为测试参数。

首次胜利固定给出旧闸钥和一种武器材料。玩家用钥匙开启岸上的旧门，通往鸣礁的栈道与回汤棚的捷径随之可达。重复挑战可产出常规材料与可选收藏，但主线不要求重复击败同一头目。初次失败后要能在短路程内重试，召唤饵的重获方式必须明确，不能用稀有消耗造成卡关。

首段的具体路径为：查看旧门边的陶片与巢痕 → 向阿汀确认背灯蟹的习性 → 领取第一份召唤饵 → 在深水闸口主动使用。首次胜利前，失败或撤退后可回阿汀处补领；首胜之后的重复挑战消耗另按普通经济验证。交互条件和背包检查须防止持有时无限重复领取，不增加额外付费通货。

### 11.6 试玩记录
邀请至少三名未读 GDD 的玩家分别试玩，作为早期发现问题的样本，不据此声称市场验证完成。记录第一次停顿的位置、原因、实际所用武器和是否需要口头提示。

- 能否独立完成一次钓鱼、看懂用途并完成制作。
- 能否描述一次受伤的原因，主动调整走位或攻击方向。
- 辅助是否把攻击带向玩家不想打的敌人，追踪是否反复绕过近处目标。
- 是否能从地标找到修缮屋、危险闸口与回程捷径。
- 战斗后是否愿意继续探索，以及最想再试哪件装备。
- 玩到结尾后是否记得一位人物、一件旧物，以及下一片区域值得去的原因。

先解决反复出现的方向、镜头、命中和目的不明问题，再增加区域或敌人数。体验不佳时，允许删减支路、精简教学和缩短路线，不通过加奖励掩盖难以操作的战斗。

## 十二 可直接制作的内容样例

### 12.1 渔获与物品链
下表给出首批可进入数据配置的样例。数量、掉率与效果强度待验证；同一物品保留一个清楚的主要用途。鱼类经过烹饪或炼化获得不同产物时，在界面中提前说明消耗关系。

| 物品 | 获得位置与主要用途 | 世界线索或体验作用 |
|------|--------------------|--------------------|
| 纸鳍鱼 | 灯汀湾普通渔获；食材或鱼骨来源 | 鳍薄如旧纸，图鉴用一句生活描述建立亲近感 |
| 灯腹鱼 | 灯汀湾外侧与夜间渔况；提取发光材料 | 腹部光色与聚落庭灯相近，提示居民曾利用当地资源 |
| 盐壳贝 | 鸣礁水域；炼化硬质壳片 | 带有规律撞痕，暗示附近敌人的捕食方式 |
| 回声鳗 | 鸣礁水域；食材与导声材料 | 身体振动与礁柱低鸣呼应，图鉴补充生态关系 |
| 铜须鲶 | 沉钟旧庭；可提取少量金属碎料 | 在旧管道周围活动，连接鱼类分布与工业遗迹 |
| 镜鳞鱼 | 无昼井庭；可选稀有制作材料 | 鳞片映出固定光斑，描述随终局认知更新 |
| 旧庭陶片 | 灯汀湾旧门旁固定调查物；推进首次线索任务 | 与后续区域餐具上的花纹对应，物品记录永久保留 |
| 工坊饭盒 | 沉钟旧庭支线调查物；交给苏苇辨认 | 让失落工程与普通人的生活发生联系 |
| 旧闸钥 | 背灯蟹首次胜利；开启岸上旧门 | 拿到后明确提示使用位置，禁止出售和炼化 |

一个可直接验证的制作链为：普通鱼 → 炼化鱼骨；壳背跳蟹 → 获得壳片；鱼骨与壳片 → 制作盐壳手炮。配方具体数量在调参后写入 JSON，避免现在凭空锁死经济。引灯杖则使用发光材料与普通结构材料，让玩家理解追踪武器为什么会呈现发光弹体。

### 12.2 三件首轮武器
**潮弧刃。** 轮廓像一段磨出弧面的旧铁片，主攻击为前方清晰的横向挥击。它让靠近敌人的风险换来较宽覆盖，适合应付正面接近和轻度包围。试验重点是动画、实际范围和敌人受击是否一致，不额外追加复杂连招。

**盐壳手炮。** 用鱼骨作握柄、壳片作护罩，发射容易看见的直射弹体。轻度辅助只改善玩家主动选择方向附近的命中，不能隔着大角度把弹体拉向身旁敌人。它用弹药消耗维持既有远程武器差异，弹药补给在测试场充足提供。

**引灯杖。** 消耗 MP 发射缓慢可辨的灯粒，发射后在限定条件下转向追踪。目标选择应接近玩家原始攻击意图，优先测试准星附近、可见且在有效距离内的敌人。具体选择权重、转弯能力、丢失目标后的行为和撞墙处理待验证；不能把它变成无视遮挡与距离的必中武器。

以上名称和外观服务既定三类攻击。后续近战、远程、魔法与召唤四类武器继续保留；召唤类在首段之后验证跟随、目标选择和视觉负担，再生产正式内容。

### 12.3 饰品与防具样例
| 装备 | 预期作用 | 调整边界 |
|------|----------|----------|
| 结绳扣 饰品 | 改善移动后的恢复手感或相关移动属性 | 具体作用只择一验证，避免同时改变闪避和攻击多个规则 |
| 灯腹坠 饰品 | 改善法力续航，支持使用魔法武器 | 不直接增加追踪角度，保留武器本身的命中特征 |
| 补网结 饰品 | 提供钓鱼相关的稳定性收益 | 与鱼竿质量、幸运和保底的分工在数值阶段确认 |
| 旅居服 防具套装 | 头、身、手、腿、鞋五部位，提供第一套基础防护 | 套装效果先采用易理解的小幅增益，避免成为所有玩法必选 |

五个饰品栏的既定结构不变。首段可以只给两件可用饰品，剩余栏位清楚展示为未装备，避免为了填满格子立即制作大量物品。装备外观首批优先在武器和整体服装上可辨；每件数值装备都换一套复杂模型不是第一阶段前提。

### 12.4 敌人生态与招式差异
| 敌人 | 行为与预告 | 对应学习和材料 |
|------|------------|----------------|
| 壳背跳蟹 | 正面靠近，压低身体后短跳扑击，落地停顿 | 学会侧移与范围近战；壳片用于基础制作 |
| 侧鳍滩蜥 | 横向移动，停顿亮出侧鳍后直线冲刺 | 练习判断方向与直射弹道；鳍膜用于轻型装备 |
| 吹盐螺 | 原地鼓起壳口，吐出慢速可见弹团 | 学会优先处理远程牵制；盐晶用于消耗品 |
| 拾光水母 | 贴近岸边低空漂浮，触须收拢后放出近身脉冲 | 练习进出攻击距离；发光材料用于魔法装备 |
| 旧庭寄壳兽 | 移动缓慢，先抬起借来的铁壳再砸地 | 识别较长前摇与恢复窗口；金属碎料用于中期装备 |
| 裂纹巡卫 | 旧设施残留的小型机械，转身校准后发射扇形慢弹 | 练习在明确间隙中移动；旧零件关联终局设施 |

首段只制作跳蟹与滩蜥。后续加入吹盐螺时，先单独介绍，再组合一个近战敌人。水母在可攻击高度活动，近战不能因高度设置而完全无效。精英变体复用既有骨架，改一项行为节奏或增加一个有预告的招式，不只叠加血量。

### 12.5 中后期头目
**盘索鳗**盘绕在沉钟旧庭的内庭水渠出口。玩家在岸台躲避沿地面的摆头横扫与有预告的吐流，等它把前段身体搭上岸沿后进攻。首版只表现可见的一段身体，其余部分藏在水面下；两阶段通过已有两招的先后顺序变化完成。通关后取出它盘踞处的机关部件，再由玩家接通岸上的升降通路。三类武器均能触及露出部位，不要求下水。

**守庭装置**是无昼井庭的终局头目，由固定底座、旋转上体和两条可见机械臂构成。低扫、定向冲击与预告落点都复用前文已经教会的阅读方式。玩家通过自由走位轮流接近它的开放面；开放面足够宽，三类武器均可攻击。约半血后组合已有招式，保留恢复窗口；不加入突然更换操作方式的载具战或必需某件稀有装备的判定。战后装置停机，打开遮板的交互和观天室揭示依次发生。

### 12.6 五条有结尾的支线
**送不出去的风铃。** 陶满希望把旧风铃送回鸣礁的旧凉亭。玩家在固定桌面找到收件人的后续留言，得知对方已经迁往安全聚落。回报是普通补给、一个可读故事，以及聚落入口挂起风铃的变化。内容只需一个道具、两处文本和一项场景开关。

**这把武器站多远。** 岑弦邀请玩家试用已经解锁的攻击类型。目标是完成清楚的试用动作并表达偏好，不比较伤害排行榜；奖励基础弹药或配方提示。此支线使用同一块安全训练空地，帮助不会主动换武器的玩家发现差异。

**名单上的空白。** 苏苇交出一份缺少下半页的旧庭迁居簿。玩家在旧庭必经侧屋找到另一页，确认一些旧邻居后来已经安顿，也有个别人未再留下记录。交付后桌面名单补全，纪念灯亮起；任务不靠随机掉落拖延情感收束。

**难看的补丁。** 陆铆认出一件旧部件上的修补痕迹，却以为它早已失效。玩家在灯汀湾旧铃塔支路看见同样补法仍在支撑钓台，带回刻有感谢语的固定铭牌；首段即可交付，奖励一条可选实用配方与他的个人回应。旧庭的后续对话补充历史。支线只加深个人感受，首次武器制作与主线通路信息均不依赖本任务。

**今晚还有一盏灯。** 首段中阿汀请玩家检查湾口旧灯，拨正被绳索遮住的灯罩并带回情况。路线复用首个钓台，完成一次简单交互即可返回交付，获得少量补给和一句回应。结局追加回访台词，这盏始终照着近岸的小灯成为玩家熟悉的归家方向。它是可选的生活小任务，不控制主线旧门的开启。

主线记录“下一步”和“为什么做”；支线可暂停，不阻断主线。任务交付、奖励发放、场景变化分别记录状态，防止重复触发。首版先完成两条支线，确认状态与文本流程可靠后扩充其余三条。

### 13.3 用户与多个 AI 如何协作
用户负责试玩与体验判断，每轮说明哪里舒服、哪里难用或无聊，以及最想先改的一件事。按需学习打开项目、F5 运行、F8 停止与查看错误，暂不要求先掌握完整开发课程。

Codex 负责主工程、代码、系统连接、排错和整合。Code Buddy 等其他 AI 可整理素材、制作独立道具或检查数据；每次分配具体文件范围，主场景、项目配置、角色和战斗连接由整合者统一修改。避免多个 AI 同时覆盖同一文件。

日常流程为：确定本轮目标 → AI 完成并检查 → 用户试玩 → 记录问题 → 下一轮。当前阶段和下一项任务记录在本章，不增加多套进度或设计文档。以后增加真人协作者时，同样按独立资源或模块划分工作。

### 13.4 AI 资源生产流程
**先写使用要求。** 每项资源先说明用途、镜头距离、轮廓、尺寸、动作、持物点、材质数量与交付格式。角色提示必须包含正面、背面和侧面一致性；3D 资源必须检查真实网格，不能只看生成预览。

**先做一个完整样例。** AI 可协助出概念草图、模型初稿、贴图、动作参考、图标、声音草案与文案。模型仍需检查拓扑、关节变形、UV、材质、碰撞、比例和导入结果；动画需确认循环、脚底滑动和攻击轨迹。具体 AI 服务等实际采购或使用时再核实能力，不预先承诺自动绑定或一键得到可用动作。

**统一后再批量。** 场景先确定岩壁、木栈道、栏杆、灯、工坊墙面等模块，再变化布局与色彩。NPC 可复用基础骨架，服饰轮廓和工作道具负责区分。武器先改攻击表现和握持轮廓，避免把大量精细模型当作内容丰富度。

**保留来源与可编辑文件。** 记录资源来源、使用条件、生成日期、采用的版本与人工修整项；按资源类型放在现有 assets 目录中。需要商用或外包前再核对具体工具条款。该记录随资源维护，不新增一套独立 GDD。

### 13.7 皮肤与发行候选
**用户意向。** 第一人称仍希望制作喜欢的外观，尤其是有专属造型与把玩感的武器、近战道具，参考《Apex Legends》传家宝的展示体验。当前只是商业化与创作方向，不代表已决定收费结构、价格或开始制作商城。（Codex）

**Codex 建议。** 优先考虑“免费 Demo 验证体验 → 正式版买断 → 有需求再做少量可选外观 DLC”。先靠完整游戏本身建立购买理由，再考虑外观增收；单人小团队暂不承担免费运营游戏的持续更新、账号、商城和付费内容生产压力。最终盈利模式未批准，销量与外观付费意愿需实际验证，不预估必然盈利。（Codex）

皮肤优先做第一人称能直接看到和操作的部位：武器／鱼竿、手套／袖口、钩爪，以及收起、取出、检视和待机把玩的表现。可做自己的原创外观与动作风格；外观不改变攻击判定，不遮住准星与敌人。完整角色皮肤可待角色展示用途清楚后再评估，既不因第一人称否定其价值，也不为卖皮肤额外扩展 MVP。（Codex）

**发行顺序建议。** 初期 Windows 测试包可用 itch.io 或直接发给试玩者；稳定后以 Steam 商店页、Demo 与愿望单作为正式发行准备，其他 PC 商店待首发流程稳定再考虑。引擎不决定必须使用哪家商店。MVP 可运行不等于已经可以正式销售或参加某期活动，内容、商店素材和日期另行核对。（Codex）
